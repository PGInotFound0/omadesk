# omadesk

AnyDesk-style remote desktop viewer for **Omarchy** (Hyprland/Wayland) — your desktop
streams to a **phone or any browser** with full pointer, keyboard, text-IME and
clipboard control. No X11, no VNC hacks, no portal dialogs: it talks Wayland
protocols directly.

```
┌────────────────────────┐          WebRTC (H.264 + DataChannel)     ┌──────────────────┐
│  Omarchy (Hyprland)    │ ─────────────────────────────────────────▶ │ Android / iOS /  │
│  omadesk server        │   screen → H.264 → browser                │  PC browser (PWA)│
│  capture · encode ·    │ ◀───────────────────────────────────────── │  touch → mouse   │
│  inject virtual input  │   taps/keys/clipboard ← phone              │  GBoard → text   │
└────────────────────────┘                                            └──────────────────┘
```

## What it does

- **Damage-driven screen capture** via `ext-image-copy-capture-v1` — the compositor
  wakes the encoder only when pixels change (tiny idle CPU), ~20–60 fps when active.
- **H.264 video + Opus audio over WebRTC** — desktop sound comes from the default
  sink monitor (`pw-record`), toggle/mute from the viewer (🔇/🔊), ~120 ms glass.
- **Input injection through Wayland itself** — `zwlr-virtual-pointer-v1` (absolute
  motion, buttons, scroll) and `zwp-virtual-keyboard-v1` (full synthetic keymap,
  dynamic Unicode keys for emoji/accents typed from the phone's IME).
  No root, no uinput, no ydotool daemon.
- **Clipboard both ways** (PC → phone and phone → PC via `wl-copy`/`wl-paste`), text only.
- **Desktop/window navigation Just Works on Omarchy**:
  - 🗂 bar: chips for workspaces 1–10 (+ window count), ◀/▶ to cycle, ↩ toggles back —
    via injected `Super+digit` / `Super+Tab` / `Super+Shift+Tab` / `Super+Ctrl+Tab`.
  - 🪟 sheet: lists every mapped window (app, title, workspace); tapping one switches
    to its workspace and click-focuses it automatically.
  - Dual gesture modes: 🖱️ tap/drag (default) and ✋ scroll mode (one-finger
    drag = wheel; tap still clicks); double-tap = double-click; two-finger drag = wheel
    in both modes; middle-click/PgUp/PgDn/Home/End/AltTab buttons in the key row.
- **GitHub-style token auth**: server prints a QR + URL; the token lives in the URL
  fragment and stays in the browser.
- **Installable PWA** — "Add to Home screen" on the phone gives an app icon.
- **Multi-monitor**: pick the output from the viewer.
- **Autostart**: systemd user service, survives reboots.

## Install

```sh
cd ~/omadesk
./install.sh          # venv + deps + ~/.local/bin/omadesk
omadesk run           # prints URL + QR in the terminal
```

Autostart on login (optional):

```sh
omadesk service-install
```

## Using it

1. On the Omarchy desktop, run `omadesk run` (or have the service running). It prints:
   - `http://<lan-ip>:9983/#<token>` — open this on the phone (same Wi-Fi/LAN)
   - a scannable QR code for the same URL
2. On the phone, tap **Connect**. The desktop appears; you're controlling it.
3. Anywhere over the internet: this machine runs **Tailscale**, so use
   `http://<tailscale-ip>:9983/#<token>` — no ports exposed, no TURN needed.

## Android app

`android/` holds a tiny WebView wrapper (no Android deps → small APK):

- first run asks for the viewer URL (the same `http://<desktop>:9983/#<token>` link),
  stores it on-device (that device-local preference is the only data it keeps);
- keeps the screen awake while connected, back-gesture navigates, ⚙ edits the URL;
- handles `omadesk://` links for one-tap deep linking.

The APK is built by GitHub Actions on every push to `main` and on new `v*` tags —
open the repo's **Actions → build-android-apk → Artifacts** for `omadesk-debug.apk`,
or check the Releases page for a tag.

To build locally yourself:

```sh
cd android && gradle assembleDebug   # needs Android SDK + JDK 17
```

## Security model

- The screen is streamed to whoever holds the token; token rotates with
  `omadesk token-rotate`.
- Server binds all interfaces by default (`--bind` to restrict). For outside-
  network use prefer Tailscale (already installed on Omarchy) or an SSH tunnel
  (`ssh -L 9983:localhost:9983 host`, then `http://localhost:9983/#token`).
- The viewer is a *full-control* remote session — treat the token like a password.

## Tested against

- Omarchy 4.0.6 (Python 3.14), Hyprland 0.56.2, single 1680×1050 monitor.
- Verified end-to-end on this machine: capture (damage-driven), pointer motion/
  click/drag (`hyprctl cursorpos` exact), text typing into bash (`echo $((40+2))`
  → 42), unicode typing (é, emoji) via dynamic keymap slots, clipboard both ways,
  decode pipeline ~45 fps.
- Known Hyprland quirk: virtual-keyboard keys are silently dropped for keycodes
  ≥~180 under some conditions (upstream issue 16517 in 0.56.2); omadesk's keyboard
  allocator avoids that zone.

## Troubleshooting

- `no token in URL` — you opened the page without the `#token` fragment; get the
  URL from the desktop terminal (`omadesk run` prints it).
- **Blank video** — check `omadesk run` log for `capture buffer`; on resolution
  change the buffer resizes automatically. If the phone is on LTE/mobile hotspot,
  the LAN discovery IP printed on the desktop won't work — use Tailscale.
- Typing symptoms after other remote tools ran (ydotool/wtype) are usually stale
  compositor key state; omadesk sweeps releases on start, but a compositor reboot
  clears everything.
